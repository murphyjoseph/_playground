## 4) Rules — Do / Don't

### Adding exports

- **MUST** export from `src/index.ts` — no exceptions
- **MUST** export types alongside values (`export type { Foo }` in `index.ts`)
- **MUST** build and verify before considering a new export stable: `pnpm --filter @repo/[name] build`
- **SHOULD NOT** export something only one consumer uses — keep it in the app

**Not like this:**

```ts
// Consumer importing a deep path — breaks if internals change
import { helper } from "@repo/[name]/src/internal/helper";
```

**Like this:**

```ts
// Consumer uses the package barrel — stable public API
import { helper } from "@repo/[name]";
// And src/index.ts exports it: export { helper } from './internal/helper'
```

### Dependencies

- **MUST NOT** add deps that push the runtime target beyond what this package declares
- **MUST** use `peerDependencies` for framework deps (UI frameworks, backend frameworks, etc.) — not `dependencies`
- **MUST NOT** add a heavy dep that only one export needs — split the package instead
- **SHOULD** prefer zero-dep implementations for utility packages; justify every runtime dep

**Dep footprint check before adding any dependency:**

1. Does this dep work in all environments this package targets (`[runtime target]`)?
2. Does every export in this package need it, or just one?
3. If just one export needs it — should that export live in a separate `@repo/[name]-[variant]` package?

### Breaking changes

- **MUST** treat any removal or rename of a public export as a breaking change
- **MUST** update all consumers in the same PR when making a breaking change
- **MUST** run `pnpm changeset` if this package is externally published
- **MUST NOT** silently change the behavior or signature of a stable export

**Finding all consumers before a breaking change:**

```bash
rg "from '@repo/[package-name]'" -l   # all source — don't restrict extensions
```

## 7) Scaffolding — Adding a New Export

1. Create `src/[feature].ts` with the implementation
2. Write tests in `src/[feature].test.ts` or `src/__tests__/[feature].test.ts`
3. Export from `src/index.ts`:
   ```ts
   export { [ExportName] } from './[feature]'
   export type { [TypeName] } from './[feature]'
   ```
4. Run `pnpm --filter @repo/[name] build` — verify it compiles
5. Run `pnpm --filter @repo/[name] check-types` — verify types export correctly
6. TSDoc the export — one-sentence summary, `@example` if usage is non-obvious (root's Comments & documentation rules)
7. If it's a breaking change: find consumers (`rg "from '@repo/[name]'"`) and update them
8. If externally published: run `pnpm changeset`

**Target file tree (complete new export):**

```
src/
├── index.ts              ← add export here
├── [feature].ts          ← implementation
└── [feature].test.ts     ← tests alongside
```
